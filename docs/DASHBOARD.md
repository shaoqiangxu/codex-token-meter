# 仪表盘时间与刷新说明

## 统计口径

所有筛选和展示时间使用北京时间 UTC+8，不受浏览器、手机或 VPS 时区影响。

| 筛选 | 起点 | 终点 |
|---|---|---|
| 今天 | 当天00:00 | 现在 |
| 最近24小时 | 现在减24小时 | 现在 |
| 本周 | 本周一00:00 | 现在 |
| 本月 | 本月1日00:00 | 现在 |
| 全部时间 | 开始监控以来的已采集数据 | 现在 |
| 自定义时间 | 输入的北京时间（包含） | 输入的北京时间（不包含），留空为现在 |

服务端边界精度为秒，统一转为 UTC 查询存储的事件。总量、项目、会话和金额使用相同边界；记录数不再截断为500条。监控默认从安装基线开始，不自动导入之前的历史。

0.1.1及更早版本的“今天”按 UTC 零点，即北京时间08:00开始，因而少算页面范围内当天00:00–08:00的已采集数据。这是显示范围问题，并非删除了这段数据。

当前生成中、活跃任务（近5分钟）和在线设备（近15秒）是当前状态，不随历史筛选变化。金额是按每条事件发生时有效的本地价格规则换算的等价费用；历史版本、单请求长上下文阈值和未知缓存写入上界仍保留。

## 刷新与交互

- 页面先读取当前范围，SSE只通知有变更；最多每秒合并一次刷新，同一页面不堆积刷新请求。
- 服务端跨页面合并同一范围的计算，已编码的JSON与gzip最多复用1秒，最多保留8种范围，避免旧页面或大量并发连接重复计算；浏览器响应仍不允许缓存。
- 时间切换立即取消旧请求，迟到的旧响应不会覆盖新范围；自定义日期不会被“今天”的实时消息覆盖。
- 选择预设或自定义日期后直接筛选；连续修改日期合并为一次请求（300ms），无需点击按钮。非法的起止时间会明确报错并保留上一次有效结果。页面也显示数据最早采集时间；如果所有数据都在今天，今天／24小时／本周／本月的总量可能相同。
- 提供加载状态、错误提示和重试。没有SSE变更时仍每15秒刷新当前在线状态；后台页面暂停自动读取。
- 数值原位更新；展开状态保留；正在选中的文本不被替换。
- 原始记录表格在首次展开时生成，每次显示100条，可继续加载；折叠时不逐行刷新。手机上表格可在自身区域横向滚动，不撑开整个页面。
- iOS日期输入带可见标签，字体不低于16px；输入／输出分行显示，管理和导出操作可折叠。

## 项目与任务归属

`msg_*` 等是日志内的消息或工具条目标识，不是用户新建的任务。旧版遗留记录只有在源日志编号唯一、且能找到同一设备上的原生任务时，才在展示时归回该任务；已有明确父任务、来源缺失或有冲突的记录不会被猜测归并。归属查询不受当前时间筛选限制，因此只查看某段历史时也能找到原任务名称。

项目显示名与仓库目录名不同会造成两张项目卡片。管理员可通过 `project_aliases` 明确统一名称（见[配置说明](CONFIGURATION.md)）。一个项目仍可包含多个真实任务；任务数按设备和原任务编号去重，不按名称去重。

以上只改变分类展示，不删除、不重新计费、不改写历史用量。项目与任务合计继续累加全部原始记录，内部条目仍可在展开的原始记录中查看；活跃任务数采用相同归属规则。

## 升级

这是服务端和网页更新，现有 Windows/Linux Agent 无需重装。升级服务后重新打开或刷新仪表盘一次即可取得带新版本号的网页资源。运行服务、回滚和备份步骤见 [运维手册](OPERATIONS.md)。

## 验证

`go test -race ./...` 覆盖跨 UTC 日期的北京时间日／周／月边界、滚动24小时、自定义参数、零点毫秒事件、历史价格一致性、SSE合并／重连和压缩响应。

`node tests/frontend_test.js` 与 `node tests/range_test.js` 覆盖稳定结构、选区、M格式、迟到响应、请求合并、失败重试和北京时间转换。

0.1.2在隔离的真实数据副本上完成浏览器验收：桌面 Chromium，以及 WebKit 的320/390/402/430px竖屏和874px横屏。检查了完整文档无横向溢出、展开记录、连续切换、自定义时间、选区保持及脚本错误。WebKit模拟不能替代实体 iPhone 的 Edge 完整验收。

0.1.5增加历史消息归属与项目别名回归测试：唯一来源、设备隔离、来源冲突、明确父任务优先、旧检查点、父任务在筛选区间外、真实任务保持独立，以及全部 Token 与历史金额保持不变。隔离数据副本同时检查了桌面 Chromium 和402px WebKit 的筛选、布局、展开及选区保持。
