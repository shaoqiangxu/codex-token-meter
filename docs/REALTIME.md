# 实时同步与真实反馈（0.1.6）

本次仅改采集调度、传输和反馈，沿用Go、SQLite spool、SSE和原生网页。未改认证、域名、部署基线、usage去重或历史价格算法；不为监控调用模型。

## 状态与数字

- 网页连接：`onopen`只表示建立连接；有效应用心跳和对应数据版本都收到后才显示“已同步”。默认5秒心跳、12秒无心跳待确认、30秒失联。无新usage不代表离线。
- 每台采集器：按服务器实际接收上报的年龄判断在线/待确认/失联。扫描失败或变旧、spool积压与上传失败单独提示。旧Agent无健康字段时显示进度未知。
- 数据：保留最后确认值及数据截至时间。主值为带千分位的完整整数，M仅辅助；`+1 Token`也可见。切换范围或合法校正允许下降。页面筛选框只过滤会话与项目列表，顶部总量仍是整个时间范围。
- 当前运行状态：可见delta为`ESTIMATED_LIVE`整数估算；有运行证据无delta为“执行中，等待usage”；明确完成才空闲；无足够证据或运行证据陈旧则未知。`EXACT`是用量质量，不是空闲状态。父任务和子任务的运行证据互不覆盖。
- 估算仅来自本地实际可读的可见输出增量，不上传正文，不估隐藏推理，不声称严格下界，不进入精确账本。精确usage到达清掉对应响应估算；无delta时不可估算。旧UI中的`LOWER_BOUND`标签改为“用量待确认”，不改历史账本。
- 450ms高亮仅改变视觉样式，精确值立即采用服务器数字，不插值、不超越目标。尊重减少动效；后台取消动画。选中的旧文本暂时保留供复制，旁边“最新精确值”即时更新；解除选择后补上显示。导出、计价永远使用权威值。

## 调度与最小化元数据

采集、上传、心跳三个独立循环。活跃文件约250ms tail；新目录发现3秒，冷文件检查10秒，归档发现/检查60秒。首次启动沿用已有检查点/EOF基线；长文件分块继续读取。spool持久化，不因网络失败丢弃；上传批次最多256条，内存唤醒队列容量1。失败指数退避1–32秒，加0–25% jitter；失败期间唤醒不会触发250ms网络重试。

检查点与对应spool入队在同一SQLite事务；网络等待不持有事务。确认响应且本地提交成功后才删除已确认队列记录。超8MiB单行明确报扫描失败并保留检查点；其他可读文件继续采集，不静默跳过usage。

健康元数据为固定类型字段：最近成功扫描、发现usage、成功上传时间，本地待上传条数，扫描/上传耗时，扫描年龄与失败标记、Agent版本/启动轮次/报告序号。现有最小会话名称元数据保留；不新增Prompt、回答、工具输出、原始日志上传。发现usage与上传时间本地持久化。

服务端记录最近精确入账时间和账本版本；页面诊断展示SSE最近发送/接收、已应用版本、快照请求含正文耗时、构建和浏览器应用耗时。设备时钟未校准，禁止用时间戳差宣称跨设备端到端毫秒延迟。RTT来自正常约30秒一次的认证`GET /api/realtime`，恢复时额外一次。

## SSE协议与有界同步

`GET /events?stream=1&period=today`使用现有认证，查询参数与快照接口相同。兼容旧`notify=1`客户端。

- `ready`：连接建立；`heartbeat`：独立的新鲜度元数据，不做历史聚合。
- `numbers`：当前查询的总量、项目合计及变更会话的**绝对值**，附移除的会话键；不推完整原始历史。
- `resync`：无基线、变更超过256KiB等情况取当前范围完整快照。
- `query_key`隔离时间范围，`server_epoch`区分进程轮次；`revision`是已物化的查询结果版本，`data_revision`是服务端数据/范围边缘变化水位，`ledger_revision`是持久化精确入账水位。心跳`revision`对应`data_revision`，不是查询结果版本。
- 推送含`base_revision`和`base_range_end`。重复/旧版本不应用；基线不匹配、版本缺口或重启取完整快照，不盲目叠加delta。并发GET不会消费其他浏览器尚未收到的推送基线。
- 最多8个查询视图缓存，每个连接只保留1条最新待发送状态；丢过中间版本的慢客户端走resync，写超时10秒，不无限积压。
- 每次通知100–250ms合并（默认200）。同一页面最多一个snapshot请求在途，期间dirty通知在完成后补拉；同范围通知不连续abort慢请求，旧范围的迟到响应不能覆盖新范围。
- 今日/周/月按北京时间；滚动24小时和秒级范围边缘用索引存在性检查触发更新，不靠心跳全历史聚合。保留原秒级查询边界，因此200ms不是端到端承诺。

网页断网后关闭并使旧流回调失效；保持最后确认数值。`navigator.onLine=true`仅触发验证，不代表连接已健康。`pageshow`/`visibilitychange`恢复时重连、立即抓当前范围快照及轻量探测，不播放后台旧动画。SSE健康时不运行15秒兜底快照轮询。

源站SSE设置`text/event-stream`、`private, no-store, no-transform`、`X-Accel-Buffering: no`并Flush。公网应观察独立心跳抵达和缓存响应；代理可能移除`X-Accel-Buffering`，不能仅据此判定有缓冲。

go vet ./...
node tests/frontend_test.js

node tests/realtime_test.js

真实10秒上传超时测试默认包含在Go测试中（`-short`可跳过）。全程只用隔离库与合成事件，不调用模型。

`TestPrepareRealtimeBrowserFixture`通过`METER_BROWSER_FIXTURE`生成新的隔离目录内4100条合成记录及测试配置。用该配置启动测试服务（仅127.0.0.1:18787），再指定`METER_BROWSER_CONFIG`运行`node tests/realtime_browser.cjs`；需要已有Playwright Chromium/WebKit，可通过`METER_PLAYWRIGHT`指定安装路径。脚本校验测试端口、合成账号和合成设备，拒绝非测试部署。`METER_BROWSER_OUTPUT`可选保存截图。不要指向生产库。

## 升级与回滚

先核对运行中的`/proc/<pid>/exe`构建信息，再核对仓库和磁盘制品；两者可能不同。备份Server和Agent的在线SQLite、现有配置及**实际运行**二进制后升级。0.1.6只新增健康/运行状态表，账本和检查点保留，兼容旧Agent。Windows需原位升级二进制才能启用新调度与健康信息，不必重新注册或重建基线。

回滚优先恢复已验证旧二进制并只重启Meter服务，保留当前数据库（旧版本忽略新增表）。Agent运行证据仍用旧协议兼容的`activity`事件。不要直接恢复旧数据库覆盖升级期间的新usage；灾难恢复须先保存当前库并核对spool与基线。具体部署备份路径和制品哈希由部署验收记录保存，不能提交含凭据配置。
